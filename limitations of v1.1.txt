2. BREAKING POINTS & LOSS ANALYSIS
========================================================================================================================

1. Data Loss:
   - AES-256-CTR is a lossless, reversible stream bijection.
   - For all audio, video, image, and binary files up to 1,000 MB, data loss was exactly 0 bytes (100% bit-for-bit SHA-256 match).

2. Storage Overhead Loss Breaking Point:
   - Fixed overhead is 82 bytes (50B V2 header + 32B HMAC tag).
   - Below 1 KB, overhead represents a large loss of storage capacity (16.02% at 512B, 6.72% at 1.2KB).
   - Above 1 MB, overhead is under 0.01%, dropping to 0.0000078% at 1 GB.

3. Latency Floor & Two-Pass Decryption Penalty:
   - scrypt KDF introduces a minimum fixed latency of ~110-160 ms regardless of file size.
   - Decryption requires two full passes over the file (Pass 1 for HMAC verification, Pass 2 for decryption), resulting in 3x file size disk I/O (2x read + 1x write).
   - At 1 GB, decrypt speed drops ~22% compared to encrypt speed (425.6 MB/s vs 549.1 MB/s).

4. All-or-Nothing Corruption Sensitivity:
   - If a single bit in a 600 MB video is corrupted, HMAC validation rejects the file completely and 100% of the data is lost to the user.

5. Disk Space Requirement:
   - Atomic replacement via temporary files requires at least 2.05x the file size in free disk space during processing.

6. Missing Metadata:
   - The vault format does not store the original filename or extension.
